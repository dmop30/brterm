# brterm 全体要件定義

最終更新: 2026-09-13 / 版: 1.0
この文書は **Claude Code Web に渡す単一の仕様書** です。リポジトリの現状、これから作る機能、
実装順、受け入れ条件までを含みます。個別の詳細は `docs/requirements-resume-and-passkey.md` を参照してください。

---

## 1. このツールは何か

ブラウザで動く SSH / SFTP ターミナルです。Windows・macOS・Linux で同じように動きます。

想定する利用者は、サーバの保守や運用を手作業で行う技術者です。彼らの一日は
「コマンドを打つ → 結果を確かめる → 設定ファイルを直す → 手順書に残す」の繰り返しで、
現状はターミナル、SFTP クライアント、エディタ、Wiki の 4 つを行き来しています。
brterm はその往復を 1 画面に畳み込むことを目的にします。

### 設計上の約束

| 原則 | 内容 |
| --- | --- |
| ネイティブ依存を増やさない | `npm install` にビルドツールを要求しない。node-pty・keytar・argon2 は採用しない |
| 既定はオフ | 新機能は設定で有効化する。既存利用者の体験と保存データを壊さない |
| 安全側に倒す | 復号できない・再接続できない・権限が足りない状況では、推測で続行せず状態を明示して止める |
| 破壊的操作は必ず確認 | 削除・上書き・再起動系は、対象を画面に出したうえで確認を取る |
| 日本語 UI | 画面文言とエラーは日本語。命令形と能動態で短く書く。サーバログは英語可 |

## 2. 現状（実装済み）

```
src/
  shared/     サーバ・クライアント共通の型と既定値
    types.ts, defaults.ts
  server/     Express + ws + ssh2
    index.ts      起動、トークン認証、静的配信
    api.ts        REST API
    ws.ts         WebSocket（端末の入出力と対話ダイアログ）
    ssh.ts        Session / SessionManager / execCommands
    sftp.ts       SFTP（接続中セッションへの相乗り）
    store.ts      db.json の読み書き
    crypto.ts     AES-256-GCM とローカル鍵
    keys.ts       鍵生成・~/.ssh/config
    scheduler.ts  cron 実行
    paths.ts      データ保存先
  client/     React 18 + xterm.js
    App.tsx, components/*, lib/*, styles/*
```

| 機能 | 状態 |
| --- | --- |
| SSH ターミナル（タブ、文字コード変換、keepalive） | 実装済み |
| 実行履歴の自動記録と手順書化（Markdown 書き出し） | 実装済み |
| 危険コマンドの実行前確認 | 実装済み |
| 予定実行（cron） | 実装済み |
| SFTP（一覧・転送・作成・改名・削除） | 実装済み |
| セッションプロファイル（文字コード・接続時コマンド・環境変数） | 実装済み |
| SSH 鍵の生成・配置・config 編集 | 実装済み |

| ファイラー・エディタ・ビューア | **未実装（本書 4 章）** |

### 技術スタック

- サーバ: Node.js 20.11+ / TypeScript (NodeNext) / Express 4 / ws / ssh2 / iconv-lite / cron-parser
- 画面: React 18 / TypeScript (Bundler) / Vite 5 / @xterm/xterm / lucide-react
- 配布: npm パッケージ（`brterm` コマンド）と Electron（electron-builder）

### 動かし方

```bash
npm install
npm run dev        # サーバ :7781 + Vite :5273（開発時はトークン認証を省略）
npm run build      # dist/client と dist/server
npm start          # ビルド済みを起動
npm run typecheck  # 型チェック（PR 前に必ず通す）
```

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| 接続先 (Host) | 登録した SSH 接続先。認証情報とプロファイルを持つ |
| セッション (Session) | サーバ側が保持する SSH 接続とシェルの組。ブラウザを閉じても生きる |
| プロファイル (Profile) | 文字コード・TERM・環境変数・接続時コマンドをまとめた設定 |
| 手順 (Procedure) | コマンドと実行結果を並べた再実行可能なドキュメント |
| 金庫 (Vault) | 接続情報とパスワードを保存する暗号化済みの保管庫 |
| ワークスペース | 画面右側のタブ領域。端末・ファイル・エディタ・設定がタブとして並ぶ |

## 4. 新機能: ファイラー / エディタ / ビューア

VS Code のリモート拡張のように、リモートのディレクトリを木構造で眺め、
その場でファイルを直し、Markdown を読める状態にします。

### 4.1 画面構成

左レールに **ファイル** セクションを追加し、選んだ接続先のツリーを常時表示します。
ファイルを開くとワークスペースに `editor` タブが増えます。端末タブと同列に並び、
Ctrl+Tab で行き来できます。

```
┌────┬──────────────┬──────────────────────────────┐
│ レ │ ファイル      │ [端末] [nginx.conf ●] [README.md] │
│ ー │ ▾ /etc/nginx │──────────────────────────────│
│ ル │   ▸ conf.d   │  1  user  www-data;             │
│    │     nginx.conf│  2  worker_processes auto;      │
│    │   ▸ sites-... │  3                              │
│    │ ▾ ~/          │                                 │
│    │     README.md │                                 │
├────┴──────────────┴──────────────────────────────┤
│ /etc/nginx/nginx.conf · UTF-8 · LF · rw-r--r-- · 未保存 │
└───────────────────────────────────────────────────┘
```

### 4.2 ツリー表示

| 要件 | 内容 |
| --- | --- |
| 遅延展開 | 開いたフォルダだけ `readdir` する。展開状態はタブが閉じるまで保持 |
| 複数ルート | ホーム、`/`、任意のパスを「ルート」として複数固定できる。接続先ごとに保存 |
| お気に入り | よく使うフォルダをピン留めしてツリー上部に出す |
| 隠しファイル | 表示切替（既定は非表示） |
| 並び順 | フォルダ優先、その中で名前順。名前・サイズ・更新日時での並べ替えを選べる |
| 絞り込み | ツリー上部の入力欄で、展開済みノードの名前を即時フィルタ |
| 仮想スクロール | 1 フォルダ 1,000 件を超えても操作が重くならないこと。2,000 件超は「先頭 2,000 件のみ表示」と明示 |
| 再読み込み | フォルダ単位とツリー全体の 2 種類 |
| 状態表示 | シンボリックリンクは矢印つきで示し、リンク先を tooltip に出す |

### 4.3 ファイル操作

右クリックメニューとツールバーから行います。

- 新規ファイル / 新規フォルダ / 改名 / 削除（フォルダは再帰確認）/ 権限変更（8 進数入力とチェックボックスの両方）
- ダウンロード / アップロード / ドラッグ＆ドロップ（ツリーのフォルダに落とせる）
- 複製、移動（同一ホスト内は `rename`、別ホストはダウンロード → アップロードで、進捗を出す）
- **パスを端末へ送る**（選択中の端末タブにパス文字列を挿入。実行はしない）
- **ここで端末を開く**（新しい端末タブを開き、`cd <パス>` を送る）
- パスをコピー / 親フォルダを開く

削除・上書き・権限変更は既存の危険コマンド確認と同じ体裁のダイアログで確認します。
`/etc`、`/boot`、`/usr`、`/var/lib` 配下の書き込みは、確認文言を強い表現に切り替えます。

### 4.4 エディタ

**採用ライブラリ: CodeMirror 6**（`@codemirror/*`）。Monaco は採用しません。
理由は、バンドルが軽く Vite との相性が良く、ネイティブ依存も追加しないためです。

| 要件 | 内容 |
| --- | --- |
| 構文強調 | shell / bash, json, yaml, xml, html, css, javascript, typescript, python, sql, markdown, ini・conf（汎用） |
| 基本編集 | 行番号、折り返し切替、検索置換、複数カーソル、インデント調整、括弧対応、元に戻す／やり直し |
| 保存 | `Ctrl+S`。一時ファイルへ書いてから `rename` で置き換える（書き込み中の破損を避ける） |
| 権限とオーナー | 保存後に元の `mode` を復元する。オーナー変更はしない |
| 改行コード | 開いた時の LF / CRLF を判定して保持する。ステータスバーに表示し、明示的に変換もできる |
| 文字コード | プロファイルの設定を既定にし、タブごとに変更できる。変更時は再読み込みする |
| 未保存の印 | タブに `●`。閉じる・再読み込み時に確認 |
| 外部変更の検知 | 保存前に `stat` で `mtime` と `size` を照合し、変わっていたら上書きせず選択肢を出す（再読み込み／差分を見る／それでも上書き） |
| 差分表示 | 保存前に「変更点を確認」で、開いた時点の内容との行差分を出す |
| 読み取り専用 | 書き込み権限が無いファイルは読み取り専用で開き、その旨をバーに出す。`sudo` での編集は行わない |
| サイズ上限 | 既定 2 MB。超えるファイルは先頭のみ読み取り専用で表示し、全文はダウンロードを促す |
| バイナリ判定 | NUL バイトを含む、または UTF-8 として不正な割合が高い場合は編集させず、情報表示にとどめる |
| バックアップ | 設定で有効にすると、初回保存時に `<name>.brterm.bak` を作る（既定オフ） |

### 4.5 ビューア

タブ内で「編集 / プレビュー / 左右分割」を切り替えます（Markdown のみ 3 モード、他は単一モード）。

**Markdown**
- CommonMark + GFM（表、取り消し線、タスクリスト、自動リンク）
- **出力は必ずサニタイズする**。生 HTML と `javascript:` スキームは通さない。ライブラリは `markdown-it` + `DOMPurify`
- 相対リンクの画像は SFTP 経由で取得して表示する（`/api/sftp/download` をエンコードして `img src` に使う）
- 相対リンクのクリックは、同じホストのファイルとしてエディタタブで開く
- 見出しから目次を作り、サイドに出す（見出しが 3 つ以上のとき）
- コードブロックは構文強調する
- 編集とプレビューのスクロールを連動させる

**画像**: png / jpg / gif / webp / svg。等倍と全体表示の切替、サイズと寸法の表示。SVG もサニタイズしてから表示します。

**ログ追尾**: `.log` などのテキストを末尾から読み、一定間隔（既定 2 秒）で追記分だけ取得して追尾表示します。
追尾は明示的な開始・停止操作とし、タブを離れたら自動で止めます。

**表形式**: csv / tsv を表として表示（読み取り専用、先頭 5,000 行まで）。

### 4.6 検索

- **名前で探す**: SFTP の再帰探索。深さ上限（既定 6）と件数上限（既定 500）を設け、途中経過を出しながら中断できる
- **中身で探す**: `exec` で `grep -rn` 相当を実行する。対象パス・除外・大文字小文字・正規表現を指定できる
  - このコマンドは brterm が組み立てるため、危険コマンド確認の対象外とする
  - 結果行のクリックで、該当ファイルの該当行にジャンプする

### 4.7 手順書との連携

設定ファイルを直す作業も手順として残せるようにします。

- エディタの「この変更を手順に残す」で、差分を含んだステップを手順へ追加する
- ステップの種類を増やす: `command`（従来）と `fileEdit`（パス・差分・保存前後のハッシュ）
- Markdown 書き出しでは、`fileEdit` を差分ブロックとして出力する
- `fileEdit` ステップの再実行はしない（誤適用を避けるため、差分の表示と手動適用の案内にとどめる）

### 4.8 API の追加（SFTP 拡張）

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/sftp/tree` | 1 階層分のノード。`hostId`, `path`, `showHidden` |
| GET | `/api/sftp/read` | ファイル内容。`hostId`, `path`, `encoding`, `maxBytes`, `offset` を受け、`{ content, encoding, eol, mode, mtime, size, truncated, binary }` を返す |
| POST | `/api/sftp/write` | `{ hostId, path, content, encoding, eol, expectMtime, expectSize, keepMode }`。`expect*` が一致しなければ `409` |
| POST | `/api/sftp/create` | 空ファイルの作成 |
| POST | `/api/sftp/copy` | 同一ホスト内の複製 |
| GET | `/api/sftp/search` | 名前での再帰検索（Server-Sent Events で途中経過を返す） |
| POST | `/api/sftp/grep` | 中身の検索（`exec` を使用） |
| GET | `/api/sftp/stat` | 単一エントリの情報 |

既存の `/api/sftp/list` は維持します（互換のため）。

### 4.9 受け入れ条件

- [ ] 接続先を選ぶとツリーが出て、フォルダを開くと中身が遅延読み込みされる
- [ ] `/etc/hosts` を開いて 1 行足し、`Ctrl+S` で保存でき、権限と改行コードが変わらない
- [ ] 別の端末から同じファイルを書き換えた後に保存しようとすると、上書きされず選択肢が出る
- [ ] 書き込み権限の無いファイルは読み取り専用で開き、保存操作ができない
- [ ] Shift_JIS のファイルが文字化けせずに開き、同じ文字コードで保存できる
- [ ] `<script>alert(1)</script>` を含む Markdown をプレビューしてもスクリプトが動かない
- [ ] Markdown 内の相対パス画像が表示され、相対リンクのクリックでそのファイルが開く
- [ ] 10 MB のファイルを開こうとすると、警告のうえ読み取り専用の先頭表示になる
- [ ] バイナリを開いても文字化けした編集画面にならない
- [ ] ツリーからファイルを右クリックして「ここで端末を開く」を選ぶと、そのフォルダで端末が開く
- [ ] 2,000 件のファイルがあるフォルダを開いても操作が引っかからない

## 5. セッション再開（詳細は別紙）

切断しても続きから再開できるようにします。詳細仕様は
`docs/requirements-resume-and-passkey.md` の「機能 A」を参照してください。要点のみ再掲します。

| 層 | 範囲 | 方法 |
| --- | --- | --- |
| L1 | ブラウザのリロード | 実装済み（`attach` と画面再送） |
| L2 | 回線断・スリープ復帰 | 切断検知 → バックオフ再接続。切断中の入力は破棄する |
| L3 | 実行中プロセスの継続 | `tmux new-session -A -s <名前>` へアタッチ。無い環境は警告のうえ従来動作 |
| L4 | brterm 再起動後 | セッションメタを `~/.brterm/sessions/` に保存し、一覧から再開 |

## 6. マスターパスキー（詳細は別紙）

起動時にツール全体のパスキーを入力させ、有効時はそのパスキーで接続情報も復号します。
詳細は同じく別紙の「機能 B」を参照。要点のみ再掲します。

- モード `local`（既定・現行互換）と `passkey` の 2 つ
- scrypt で KEK を導出 → DEK をラップ。パスキー変更は再ラップのみ
- 暗号化範囲は `secrets` と `full`（既定）。`full` では接続先・履歴・手順も暗号化
- ロック中は `/api/vault/*` 以外を `423` で拒否し、予定実行はスキップして記録する
- 自動ロック時も既存の SSH セッションは維持する

**本章と 4 章の関係**: パスキー有効時、エディタが開いたファイルの内容はディスクに残しません。
未保存の内容もサーバ側に保存せず、ブラウザのメモリ上だけで保持します。
ロック中はツリーもエディタも開けません（パス名が漏れるため）。

## 7. 非機能要件

| 分類 | 要件 |
| --- | --- |
| 対応環境 | Node.js 20.11+。Windows 10+ / macOS 12+ / 主要な Linux。ブラウザは Chrome・Edge・Firefox・Safari の最新 2 版 |
| 性能 | 端末の入力から表示まで体感遅延なし。ツリー 2,000 件、エディタ 2 MB で操作が引っかからない |
| 起動 | `npm start` から画面表示まで 3 秒以内（接続処理を除く） |
| 安全性 | 既定は 127.0.0.1 待ち受け。トークン認証と Origin 検証。ホスト鍵の指紋確認。秘密情報はログに出さない |
| 操作性 | 主要操作にキーボードショートカット。フォーカスの可視化。`prefers-reduced-motion` の尊重 |
| 表示 | 暗い配色と明るい配色の 2 テーマ。日本語フォントで崩れないこと |
| 国際化 | 当面は日本語のみ。文言はコンポーネント内に直書きで可（将来の抽出を妨げない書き方にする） |
| 依存 | ネイティブアドオンを含む依存を追加しない。`npm install` がビルドツール無しで完了すること |

## 8. データの保存

`~/.brterm`（Windows は `C:\Users\<名前>\.brterm`）。

| ファイル | 内容 | 暗号化 |
| --- | --- | --- |
| `db.json` / `db.enc` | 接続先・プロファイル・手順・予定・履歴・設定・既知のホスト鍵 | `passkey` + `full` のとき全体 |
| `master.key` | ローカル鍵（`local` モードのみ） | — |
| `vault.json` | KDF パラメータ、ラップ済み DEK、検証子 | — |
| `token` | 画面アクセス用トークン | — |
| `sessions/` | 再開用のセッションメタとスクロールバック | パスキー有効時 |
| `logs/` | 予定実行のログ | しない（機密を書かない方針） |

## 9. 実装の進め方

各フェーズを 1 つの PR にします。フェーズ内の項目はすべて終えてから次へ進みます。
**どのフェーズでも `npm run typecheck` が通ることを完了条件に含めます。**

### フェーズ 1: 土台の整理
- [ ] `src/shared/types.ts` に本書で追加する型（`ResumeConfig`、`FileTab`、`ProcedureStep.kind` など）を定義
- [ ] `src/server/crypto.ts` を DEK / KEK 方式へ作り替え（`vault.ts` として切り出す）。`local` モードで現行と同じ結果になること
- [ ] `store.ts` のスキーマ版数を 2 に上げ、旧 `db.json` からの移行処理を入れる

### フェーズ 2: マスターパスキー
別紙「機能 B」のフェーズ 2 の内容をそのまま実施します。

### フェーズ 3: 自動再接続（L2）
別紙「機能 A」のフェーズ 3。

### フェーズ 4: リモート多重化と再起動復元（L3・L4）
別紙「機能 A」のフェーズ 4・5。

### フェーズ 5: ファイルツリー
- [ ] `/api/sftp/tree`、`/api/sftp/stat` を追加

## 11. スコープ外

- ローカルシェル（自分の PC の端末）。`node-pty` が必要なため
- 多段接続（ProxyJump）。`~/.ssh/config` の記述は読むが接続には使わない
- `sudo` を伴うファイル編集。権限昇格の自動化は事故につながるため行わない
- LSP・補完・デバッガなどの本格的な IDE 機能。エディタは「設定ファイルを直せる」水準にとどめる
- Git 連携
- パスキーのリカバリーコード発行（暗号化バックアップの書き出しで代替する）
- 過ぎた予定実行の取り返し運転
- 複数利用者の管理・権限分離。1 人 1 プロセスで運用する

## 12. Claude Code への依頼事項

1. フェーズ順に実装し、フェーズごとにコミットを分けること
2. 既存の書き方（日本語コメント、`src/shared` 経由の型共有、`.js` 拡張子つきの相対 import はサーバ側のみ）に合わせること
3. 画面の文言は本書の表現を使い、新しい語彙を勝手に増やさないこと
4. 依存を追加するときは 4.10 の一覧に限り、それ以外が必要になった場合は理由を添えて提案すること
5. 破壊的な操作を伴う機能では、確認ダイアログの文言に**対象のパスまたはホスト名を必ず含める**こと
6. 不明点があれば実装を止めて質問すること。推測で仕様を決めないこと
